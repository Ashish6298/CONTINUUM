1. PHASE REQUIREMENTS & SPECIFICATION AUDIT
--------------------------------------------------------------------------------
Phase 82 reviews all critical flows (create, capture, resume, history, branch,
restore, backup, export, import, search) and validates error, empty, loading,
confirmation, and recovery user experience across Project Continuum:

- Error State Guarantees:
  * Errors state explicitly:
    1) What failed (`what_failed` string).
    2) Whether data was committed (`data_committed: bool` and `data_committed_statement`:
       "NO (Authoritative records remain unchanged)").
    3) Actionable next steps (`next_steps` / `suggested_action`).
  * Automatic zero-secret-leakage sanitization: tokens (e.g., GitHub PATs, AWS
    keys, passwords, Bearer tokens) are scrubbed and redacted from error messages
    via `_sanitize_error_text()` and `sanitizeTextForDisplay()`.

- Confirmation & Destructive Action Safeguards:
  * Restoring historical checkpoints, deleting records, and creating branches
    explain consequences clearly in pre-flight previews and dialog prompts.
  * Cancellation never mutates data: if user cancels or presses Escape,
    no HTTP mutation requests are sent, authoritative storage remains untouched,
    and the UI confirms: "Restore cancelled. No data was modified."

- Accessible Dialog & Focus Management:
  * Modals implement `role="dialog"`, `aria-modal="true"`, and label relationships.
  * Opening a dialog tracks the previous focused element (`this.lastFocusedElement = document.activeElement`).
  * Dismissing a dialog (Close button, Cancel button, Escape key, or submission)
    reliably returns keyboard focus to the triggering element.

- Empty, Loading & Recovery UX:
  * Empty search results display dedicated empty state with "Reset Filters"
    and "Rebuild Index" recovery buttons.
  * Empty archives (0 records) are inspected and handled safely without corruption.
  * Resilient recovery on storage and search index failures: operational errors in
    SQLite FTS5 index fall back gracefully and report user-safe recovery guidance
    without corrupting authoritative JSON records.
  * Loading & in-flight states: buttons set `aria-busy="true"` and `disabled` to prevent
    duplicate submissions and visually indicate progress.

- Gate Invariant Verification:
  * "UI never implies false success": Failed or cancelled actions return error status
    or explicit cancellation notices. Success notifications are triggered strictly
    after verified 2xx HTTP confirmations.
