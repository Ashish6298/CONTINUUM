1. PHASE OVERVIEW & REQUIREMENTS IMPLEMENTATION
--------------------------------------------------------------------------------
Phase 73 implements policy-driven, non-destructive history retention and ancestry
protection, preventing runaway disk storage while strictly enforcing that required
checkpoints and branch ancestries are never silently deleted.

Key Architectural Guarantees:
1. Multi-Target Policies (`core.retention.RetentionPolicy`):
   - `max_checkpoints`: Maximum checkpoint depth allowed per activity.
   - `max_age_days`: Time-based expiration cutoff in days.
   - `max_storage_bytes`: Cumulative checkpoint byte budget.
   - Configurable safety switches: `protect_branch_origins`, `protect_explicitly_flagged`,
     and `create_undo_backup`.

2. Guarded Ancestry & Protected Checkpoints (I-11):
   - Current active branch head is ALWAYS protected and cannot be deleted.
   - Branch origins (checkpoints referenced by other activities via
     `branch_source_checkpoint_id`) are STRICTLY protected.
   - User-flagged checkpoints (`metadata.is_protected=True`) are preserved.
   - Pruning walks candidates from oldest to newest, only touching non-protected nodes.

3. Pre-Flight Preview & Impact Summary:
   - `preview_retention()` executes a strictly read-only evaluation.
   - Calculates exact breakdown: total, protected, candidates, reclaimable bytes.
   - Accurately details protection reasons per checkpoint.
   - Flags `limit_satisfied=False` if limits cannot be met safely due to protected ancestry.

4. Safe Pruning & Zero-Data-Loss Undo:
   - Atomic unlink of pruned records with synchronized deletion in `checkpoints_idx`
     and `search_fts`.
   - Pruned files automatically archived into `.continuum/retention_backup/<session>/`.
   - Full undo capability: `restore_retention_backup()` reinstates files and re-indexes.
   - Automatic rollback from backup if an unexpected exception occurs during pruning.

5. Gate Invariant:
   - Gate Condition: "No blind deletion loop."
   - When requested limits cannot be achieved without violating protected checkpoints,
     the engine stops, refuses to delete protected nodes, and explains clearly via
     `RetentionPreviewReport.explanation`.
