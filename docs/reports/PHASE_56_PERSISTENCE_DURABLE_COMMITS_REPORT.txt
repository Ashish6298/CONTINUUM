1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Phase 56 initiates Milestone 37 (Durable Storage and Migration) for Project
Continuum v1.4.0 "Universal Resume Anywhere". Conforming to ADR-001 (accepted in
Phase 55), this phase delivers:
1. `ActivityCheckpointStore`: Durable, crash-safe persistence for Activities and
   Universal Checkpoints.
2. Hybrid Architecture:
   - Authoritative Store: Partitioned, human-readable JSON files:
     `<workspace_root>/.continuum/activities/<activity_id>/activity.json`
     `<workspace_root>/.continuum/activities/<activity_id>/checkpoints/<checkpoint_id>.json`
   - Derived Index Store: Embedded SQLite database (`.continuum/index.db`) using
     Python's standard library `sqlite3` (strictly zero third-party dependencies).
3. Accurate Commit Confirmation (I-02): Writes to a PID-isolated `.tmp` file, flushes
   buffers, forces OS disk synchronization (`os.fsync`), and atomically swaps
   (`replace()`) before updating the SQLite index and returning confirmation.
4. Prevention of Partial Records & Dangling Relations:
   - Committing a checkpoint requires an existing parent activity (`ActivityNotFoundError`).
   - If `parent_checkpoint_id` is supplied, parent existence is verified
     (`DanglingReferenceError`).
   - If file write or indexing fails, temporary files are pruned, target files are
     not left in partial state, and `CommitFailedError` is raised.
5. Bounded Pagination (I-17): List operations accept `limit` (default 20, clamped to
   max 100) and `offset` for high-performance sub-millisecond timeline queries.
6. Non-Authoritative Index Recovery (I-06): If `.continuum/index.db` is missing or
   corrupted, `rebuild_index_from_authoritative_files()` deterministically reconstructs
   the entire SQLite index from the JSON partitions.

3. ARCHITECTURAL CONTRACTS & INVARIANTS ENFORCED
--------------------------------------------------------------------------------
A. Two-Phase Atomic Commit (I-02):
   - Every file write targets a temporary file: `<name>.tmp_<pid>`.
   - File is explicitly synced via `os.fsync(f.fileno())`.
   - Replaced atomically using `tmp_file.replace(target_file)`.
   - Connection closed cleanly with a managed `@contextmanager` to prevent
     Windows NTFS file locking (`WinError 32`).
   - Success is only confirmed to callers after both disk sync and index succeed.

B. Relational Integrity & Dangling Reference Prevention:
   - `commit_checkpoint` rejects checkpoints referencing non-existent activities with
     `DanglingReferenceError`.
   - `commit_checkpoint` rejects checkpoints referencing non-existent parent checkpoints
     with `DanglingReferenceError`.
   - Preserves causal DAG lineage across the entire activity lifecycle.

C. Bounded Memory Retrieval (I-17):
   - `list_activities(limit, offset)`: Clamps limit to `MAX_PAGE_LIMIT = 100`.
   - `list_checkpoints(activity_id, limit, offset)`: Clamps limit to 100.
   - Enables handling 50,000+ checkpoints without memory bloat or latency spikes.

D. Derived Index Resilience (I-06):
   - Deleting `.continuum/index.db` causes zero data loss.
   - Calling `rebuild_index_from_authoritative_files()` re-indexes all activities
     and checkpoints losslessly.
