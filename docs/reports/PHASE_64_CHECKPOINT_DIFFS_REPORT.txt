1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Phase 64 of Project Continuum v1.4.0 "Universal Resume Anywhere" implements the
deterministic, bounded Checkpoint Comparison and Diff Engine. Conforming strictly
to Invariant I-03 (Never Rewrite History / Read-Only History) and Invariant I-17
(Bounded Queries, Diffs & Search Bounds), this phase delivers:
1. Multi-Faceted Checkpoint Comparison:
   - Evaluates compatible UniversalCheckpoints for:
     * Progress transitions (numerical value, percentage deltas, and direction).
     * Completed work evolution (newly finished items, retracted items, persisting).
     * Pending actions evolution (newly scheduled actions, resolved/cleared actions).
     * Architectural decisions & rationale (new decisions, modified decisions with
       rationale/constraint evolution, removed decisions).
     * Blockers & unresolved issues (newly detected, resolved blockers, persisting).
     * Notes and context text diffs (unified diff format with line-by-line attribution).
     * Structured state differences (added, removed, and changed state keys/values).
     * Artifact metadata evolution (added, removed, modified size/checksum without
       loading large file payloads).
2. Pure Non-Destructive Invariant (I-03):
   - Comparison is a strictly pure functional operation that never modifies disk files,
     never touches database indices, and never mutates source checkpoints or timestamps.
3. Strict Output Bounding & Memory Protection (I-17):
   - Large list diffs are clamped to `max_list_items` (default 100, max 500) with
     `is_truncated=True` flags.
   - Long context diffs are clamped to `max_text_diff_chars` (default 4000) with explicit
     truncation notices.
   - Raw artifact content (`snapshot_content`) and large file payloads on disk are
     strictly NEVER loaded into memory or serialized into diff output; only metadata
     (path, size, checksum, change type) is inspected.
4. Deterministic & Understandable Output Gate:
   - Set differences are sorted deterministically so repeated runs produce exact
     byte-for-byte identical JSON and Markdown payloads.
   - Generates human-understandable Markdown diffs with clear visual headers and
     change symbols (`[+] Added`, `[-] Retracted`, `[✓] Resolved`, `[Δ] Modified`).
5. REST API & Web Dashboard Integration:
   - `GET /api/v1/checkpoints/compare`: Query parameters for base_id, target_id,
     activity_id, format (json/markdown), max_items, and max_chars.
   - `POST /api/v1/checkpoints/compare`: Programmatic JSON endpoint.
   - Interactive UI: "Compare with Parent" action in snapshot inspection drawer and
     dedicated Checkpoint Comparison Modal in the Web Control Dashboard.

3. ARCHITECTURAL CONTRACTS & INVARIANTS ENFORCED
--------------------------------------------------------------------------------
A. Non-Destructive Invariant (I-03):
   - Verified that running multiple comparisons across disk-persisted checkpoints leaves
     file sizes, modification times (`st_mtime_ns`), and SHA-256 content hashes 100%
     bit-for-bit unchanged.
   - History is never rewritten.

B. Bounded Query & Memory Invariant (I-17):
   - Checkpoint diffs clamp output to prevent unbounded JSON/Markdown payloads.
   - Large artifacts are guarded: only metadata attributes (checksum, size_bytes, path)
     are compared; artifact bodies are never read into memory.

C. Compatibility & Error Guarding:
   - Cross-activity comparisons are rejected with clear explanation by default.
   - Missing or corrupted checkpoint references safely return HTTP 404 / 400 errors
     instead of unhandled crashes.
