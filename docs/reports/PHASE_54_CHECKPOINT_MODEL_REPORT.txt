1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Phase 54 implements the core Checkpoint and Provenance domain model for Continuum
v1.4.0 "Universal Resume Anywhere". Conforming to invariants I-01 (Stable IDs),
I-06 (Authoritative vs Derived Briefs), I-08 (Provenance Types), I-09 (Snapshots vs
Live References), and I-18 (Schema Backward Compatibility), this model enables
universal continuity across any AI model, tool, or IDE.

Key capabilities delivered:
- `UniversalCheckpoint` model with unique immutable ID (`chk_<hex>`), activity association
  (`activity_id`), chronological timestamp, parent ancestry (`parent_checkpoint_id`),
  and progress percentage.
- First-class structured domain entities:
  * `completed_work`: List of completed tasks with timestamps and evidence.
  * `pending_actions`: Prioritized next tasks with blockers.
  * `decisions`: Architectural and design rationales (`DecisionRecord`).
  * `blockers`: Active impediment strings.
  * `artifacts`: References to workspace files or code snapshots (`ArtifactReference`),
    supporting `REFERENCE` (live file path/hash) and `SNAPSHOT` (inlined content).
  * `provenance`: Granular origin tracking (`ProvenanceRecord`) distinguishing
    USER_CONFIRMED, AUTOMATIC_CAPTURED, IMPORTED, and AI_GENERATED content.
  * `resume_brief`: Derived, non-authoritative resume instructions (`ResumeBrief`).
  * `structured_state`: Underlying 3-State engine snapshot dictionary.
- Strict separation of authoritative fields from derived briefs: summaries or briefs
  are never treated as primary ground truth (I-06).
- Full backwards compatibility with legacy `HandoffCheckpoint` records (I-18).

3. ARCHITECTURAL INVARIANTS ENFORCED
--------------------------------------------------------------------------------
A. Authoritative vs Derived Fields (I-06):
   The authoritative ground truth of any checkpoint is stored in its structured
   fields (`completed_work`, `pending_actions`, `decisions`, `blockers`, `artifacts`,
   `structured_state`, `provenance`). The `resume_brief` is explicitly designated as
   a derived summary (`is_authoritative = False` by default). Restoring an activity
   or rebuilding state always hydrates from authoritative fields.

B. Multi-Tier Provenance (I-08):
   Every checkpoint and discrete item can declare provenance via `ProvenanceRecord`:
   - `USER_CONFIRMED`: Directly entered or confirmed by the human engineer.
   - `AUTOMATIC_CAPTURED`: Harvested by filesystem watchers, git status, or test runners.
   - `IMPORTED`: Ingested from external chat transcripts, markdown exports, or tools.
   - `AI_GENERATED`: Proposed or drafted by an LLM / AI agent.

C. Live References vs Code Snapshots (I-09):
   `ArtifactReference` tracks files using two modes:
   - `ArtifactMode.REFERENCE`: Stores `file_path`, `content_hash`, and line numbers
     pointing to live workspace files.
   - `ArtifactMode.SNAPSHOT`: Stores explicit content in `snapshot_content` for
     crash or disaster recovery when files may be deleted or modified.

D. Legacy Backward Compatibility (I-18):
   `UniversalCheckpoint.from_legacy_handoff_checkpoint()` provides lossless migration
   from existing `core.state_models.HandoffCheckpoint` objects, extracting
   `pending_actions`, `decisions`, and `completed_work` while setting provenance to
   `AUTOMATIC_CAPTURED`.
