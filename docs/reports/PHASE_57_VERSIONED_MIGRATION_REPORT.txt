1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Phase 57 implements the versioned, idempotent data migration engine for Project
Continuum v1.4.0 "Universal Resume Anywhere". Conforming to invariants I-14
(Validated, Recoverable, Idempotent Migration) and I-18 (Backward Compatibility),
this phase delivers:
1. `ContinuumMigrator`: Automatic schema version detection, migration planning,
   dry-run preview, and robust execution.
2. Verified Pre-Migration Backup: Prior to mutating any live data, an immutable
   recovery snapshot is captured in `<workspace_root>/.continuum/backup/pre_migration_<timestamp>/`.
3. Conservative Record Mapping:
   - Root Workspace Activity: Legacy `state.json` is mapped into a persistent root
     activity (`act_migrated_workspace`) and active checkpoint (`chk_migrated_active_1_0_0`).
   - Legacy Handoffs: Files in `.continuum/handoffs/` are mapped via
     `UniversalCheckpoint.from_legacy_handoff_checkpoint()`, preserving IDs,
     timestamps, model metadata, and provenance.
   - Legacy History: Snapshots in `.continuum/history/` are safely converted into
     historical checkpoints linked to the root activity.
4. Idempotency & Repeat Runs: Re-running migration on an already upgraded or partially
   upgraded workspace produces zero duplicate records and safely confirms success.
5. Malformed Input & Unsupported Versions:
   - Corrupted or non-JSON files are quarantined and cataloged in `records_skipped`.
   - Unsupported schema versions (e.g. unknown future versions) are rejected with
     typed `MigrationError`, leaving live data untouched.
6. Post-Migration Verification Gate: Rebuilt entities are verified against
   `ActivityCheckpointStore` and SQLite index before writing `.continuum/migration.json`.
   Catastrophic failures trigger automated rollback.

3. ARCHITECTURAL CONTRACTS & INVARIANTS ENFORCED
--------------------------------------------------------------------------------
A. Idempotency & Replay Safety (I-14):
   - Migrations can be run repeatedly without duplicating activities or checkpoints.
   - `detect_version()` evaluates `.continuum/migration.json` and partitioned activity
     directories to short-circuit redundant passes.

B. Pre-Migration Recovery Point (I-14):
   - `create_pre_migration_backup()` copies `state.json`, `history/`, and `handoffs/`
     into timestamped directories under `.continuum/backup/`.
   - `rollback()` safely restores from backup if post-migration verification fails.

C. Preservation of IDs, Provenance & Lineage (I-18):
   - Original checkpoint IDs (e.g. `chk_handoff_legacy_01`) are preserved.
   - `ProvenanceRecord` records original model metadata, schema versions, and timestamps.
   - Forward and backward compatibility maintained across all supported legacy schemas.

D. Resilient Skipping of Corrupted Fixtures:
   - Partial or unparseable files do not halt migration. They are logged in
     `records_skipped` with human-readable error reasons.
