1. OBJECTIVES AND SCOPE
--------------------------------------------------------------------------------
Phase 69 delivers an accessible, unified search interface and robust filtering
engine across activities and checkpoints, with result context and state
differentiation:
1. Search Filters & Controls:
   - Target / Record Type: All Records, Activities Only, Checkpoints Only.
   - Status: All Statuses, active, paused, completed, archived.
   - Type: All Activity Types, coding, study, research, writing, work_task,
     ai_agent, custom.
   - Date: Presets (Today, Past 7 Days, Past 30 Days) and ISO ranges (date_from,
     date_to).
   - Tags: Case-insensitive tag matching and multi-tag filtering.
   - Collection: Filter by activity collection grouping.
   - Query & Filter Reset: Dedicated clear/reset actions.
2. Result Context & History Differentiation:
   - Owning Activity: Resolves and displays owning activity title and ID.
   - Checkpoint Date: Formatted timestamps and machine-readable datetime tags.
   - State Distinction: Distinguishes current active state (Head checkpoint,
     badge: [CURRENT STATE]) from historical checkpoints (badge: [HISTORICAL])
     and activities (badge: [ACTIVITY]).
   - Interactive Navigation: Direct action buttons to "View Snapshot" in modal
     or "Resume Activity" in Universal Resume Center.
3. Bounded Excerpts & Pagination:
   - Excerpt character bounding (max 280-300 chars) preserving balanced <mark>
     tags with ellipsis.
   - Server-side and client-side bounded pagination with limit/offset and page
     navigation controls (Previous, Next, Page X of Y).
4. States & Accessibility:
   - Explicit states: Empty prompt, loading spinner, no-match suggestions,
     syntax/query error recovery, and stale index rebuild action.
   - Screen-reader accessible: aria-live="polite" summary announcements,
     semantic roles (region, feed, article), and full keyboard navigation.
   - Keyboard shortcuts: Alt+S toggles search view, Esc closes search, Enter
     submits search.
   - Responsive layout adapting gracefully from desktop multi-column to mobile.

2. GATE VERIFICATION

3. INVARIANTS COMPLIANCE
--------------------------------------------------------------------------------
- I-01 (Stable IDs): Search results preserve and link authoritative activity IDs
  and checkpoint IDs regardless of renames or metadata updates.
- I-03 (History Immutability): Search operations are strictly read-only and
  never mutate activities, checkpoints, or timeline history.
- I-06 (Derived Index Rebuildability): Search index is fully rebuildable from
  authoritative disk JSON files at any time via store.rebuild_search_index()
  or POST /api/v1/search/rebuild.
- I-10 (Secret Redaction & Privacy): Excerpts and search records are sanitized
  using DaemonSanitizer; secrets and tokens are redacted before display.
- I-17 (Bounded Output & Memory): Limits are clamped between 1 and 100, and
  excerpts are strictly bounded in character length to prevent unbounded memory
  or DOM explosion.
