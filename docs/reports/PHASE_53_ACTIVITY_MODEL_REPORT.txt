1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Phase 53 initiates Milestone 36 (Domain Model and Invariants) of the Continuum
v1.4.0 "Universal Resume Anywhere" engine. The primary objective is to define the
first-class `Activity` and lifecycle model conforming to invariants I-01 (Stable IDs),
I-16 (State Machine Valid Transitions), and I-17 (Audit / Non-Destructive Lifecycle).

The model supports:
- Canonical Activity ID format (`act_<hex>`) generated via UUIDv4, strictly preserved
  across renames, edits, and status changes.
- Valid status transitions: ACTIVE <-> PAUSED, ACTIVE <-> COMPLETED, ACTIVE <-> ARCHIVED,
  PAUSED <-> ARCHIVED, COMPLETED -> ARCHIVED, COMPLETED -> ACTIVE (reopening),
  and ARCHIVED -> ACTIVE / PAUSED (recovery).
- Prohibited invalid transitions (e.g. COMPLETED -> PAUSED without reopening).
- Built-in and custom activity types (FEATURE, BUGFIX, REFACTOR, INVESTIGATION,
  RELEASE, EXPERIMENT, AUDIT, CUSTOM).
- Blank activity creation as well as built-in templates (blank, feature_implementation,
  bug_fix, refactoring, code_audit).
- Strict user input validation (rejecting empty titles, bad status strings, invalid tags).
- Non-destructive audit history where status transitions and edits never delete prior
  history or mutate historical created_at timestamps.

3. MODEL SPECIFICATION & LIFECYCLE INVARIANTS
--------------------------------------------------------------------------------
A. Identity & Preservation (I-01):
   Every activity possesses an immutable `id` prefixed with `act_`. Renaming the title,
   altering the purpose, or transitioning state updates `updated_at` while strictly
   preserving `id` and `created_at`.

B. Status State Machine (I-16):
   Allowed transitions:
   - ACTIVE    -> PAUSED, COMPLETED, ARCHIVED
   - PAUSED    -> ACTIVE, ARCHIVED
   - COMPLETED -> ACTIVE (reopening), ARCHIVED
   - ARCHIVED  -> ACTIVE, PAUSED (recovery)
   Disallowed transitions:
   - COMPLETED -> PAUSED (rejected; must reopen to ACTIVE first)
   - ARCHIVED  -> COMPLETED (rejected; must recover to ACTIVE first)

C. Non-Destructive Lifecycle (I-17):
   Archiving an activity marks `status = ActivityStatus.ARCHIVED`. It never purges,
   overwrites, or deletes the record. Reopening a completed activity marks
   `status = ActivityStatus.ACTIVE`.
