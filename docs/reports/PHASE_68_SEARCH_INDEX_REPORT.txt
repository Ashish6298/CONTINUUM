1. OBJECTIVES AND SCOPE
--------------------------------------------------------------------------------
Phase 68 implements local, offline full-text search across Continuum activities and
checkpoints, indexing rich contextual state while maintaining strict secret protection
and data isolation.

Key requirements delivered:
1. Search Source Coverage:
   - Activities: title, description, tags, type, status, collection, date.
   - Checkpoints: context, notes (intent, blockers, progress), decisions
     (decision text and rationale), actions (completed work and pending actions),
     resume briefs (purpose and next actions), permitted artifact metadata
     (name and relative paths), inherited tags, type, status, collection, date.
2. Rebuildable Derived Index:
   - Search index (search_fts virtual table using SQLite FTS5) is completely
     derived and rebuildable from the authoritative filesystem JSON files (I-06).
   - Rebuilding can be invoked via store.rebuild_search_index(), store.rebuild_index_from_authoritative_files(),
     or POST /api/v1/search/rebuild.
3. Authoritative Isolation and Non-Blocking Commit:
   - Authoritative JSON persistence occurs first and independently.
   - Search indexing is performed after commit succeeds; indexing errors or
     failures are non-blocking and never corrupt or roll back authoritative records.
4. Excluded Content and Secret Redaction (I-10):
   - High-risk credential and certificate files (.env, id_rsa, *.pem, *.key,
     secrets.json) are strictly excluded from artifact search metadata.
   - Text containing inline tokens (AWS keys, GitHub tokens, OpenAI keys, JWTs)
     is automatically sanitized (<REDACTED_*>) prior to indexing and in snippets.
5. Query Correctness:
   - Supports keywords, quoted phrases ("API Gateway"), prefix wildcards (Gate*),
     and sanitizes special characters (: ( ) { } ^ @) to prevent FTS5 syntax errors.
   - Supports filtering by record_type, activity_id, status, type, tag, collection,
     and date ranges.
   - Enforces bounded pagination (default limit 20, max limit 100, offset).
6. REST API Endpoints:
   - GET /api/v1/search (query parameters: q, record_type, activity_id, status, tag, collection, limit, offset)
   - POST /api/v1/search (JSON request payload)
   - POST /api/v1/search/rebuild (rebuilds FTS5 index from disk files)
