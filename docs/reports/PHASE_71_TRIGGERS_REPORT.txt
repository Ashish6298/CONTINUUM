1. PHASE OVERVIEW & REQUIREMENTS IMPLEMENTATION
--------------------------------------------------------------------------------
Phase 71 establishes configurable, privacy-first automatic triggers that support
automated continuity checkpoints while strictly enforcing that automation NEVER
bypasses privacy controls or data validation.

Key Architectural Guarantees:
1. Authoritative Baseline Invariant (I-01):
   - Manual capture always remains the authoritative baseline and is never superseded
     or bypassed by automated triggers.
   - Manual captures produce `user_confirmed` authoritative records (`is_authoritative=True`),
     whereas automated triggers create non-authoritative `auto_captured` records
     (`is_authoritative=False`).

2. Supported Integration Events:
   - GIT_COMMIT: Reliable git integration event capturing commit hash, branch, message,
     and changed file artifact references.
   - MEANINGFUL_CHANGE: Filesystem delta event triggering only when changes exceed
     configurable file count thresholds (default: 3 files) matching relevant code/doc
     extensions.
   - SCHEDULED: Periodic time-based triggers enforcing configured intervals (e.g. 1800s)
     and minimum safety cooldown periods (default: 300s).

3. Individually Opt-In Configuration:
   - All triggers default to disabled (`False`).
   - Each trigger must be individually opt-in and enabled.
   - Configuration is stored reliably in `.continuum/triggers.json` via atomic swaps.

4. Deduplication & Idempotency:
   - Uses deterministic SHA-256 event fingerprinting across a configurable time window
     (`dedup_window_seconds`).
   - Duplicate git commits or identical changed filesets within the window are skipped
     with clear explanations.

5. Safe Retry & Error Isolation:
   - Bounded retries (`max_retries`, `retry_delay_seconds`) with error isolation.
   - Storage failures or unresolvable activities are cleanly logged and reported
     without corrupting repository history or halting daemon execution.

6. Strictly No Unrestricted Background Monitoring:
   - Event evaluations are passive/on-demand.
   - Mandatory cooldown periods prevent infinite capture loops.

7. Privacy Guards & Sanitization Invariant:
   - Gate Invariant: "Automation never bypasses privacy or validation."
   - Every automated checkpoint passes through `DaemonSanitizer`:
     * Regex inline secret redaction (API keys, tokens, credentials, DB URIs).
     * Custom denied terms redaction.
     * High-risk credential and certificate files (`.env`, `id_rsa`, `*.pem`, `*.key`,
       `credentials.json`) are strictly excluded from artifact references.
     * Host paths normalized to workspace-relative POSIX format.

2. REST API ENDPOINTS
--------------------------------------------------------------------------------
The following endpoints were implemented and validated:
- `GET /api/v1/triggers/status` (also `/api/v1/triggers/config`):
  Returns active configuration, last execution timestamps, and recent bounded history.
- `POST /api/v1/triggers/config`:
  Updates opt-in flags, file thresholds, cooldowns, and privacy settings.
- `POST /api/v1/triggers/evaluate`:
  Evaluates incoming integration events (`git_commit`, `meaningful_change`, `scheduled`)
  and safely triggers atomic checkpoint commits if eligible.
