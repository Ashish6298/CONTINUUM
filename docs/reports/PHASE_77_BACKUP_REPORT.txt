1. PHASE OVERVIEW & REQUIREMENTS IMPLEMENTATION
--------------------------------------------------------------------------------
Phase 77 implements the Complete Backup subsystem for Project Continuum, delivering
authoritative, self-contained, and integrity-verified backup archives with streaming
bounded-memory execution (I-17), honest encryption disclosure, and relation validation.

Key Architectural Guarantees:
1. Strict Scope Definition (`core.backup.BackupScope`):
   - Authoritative Included Content:
     * Activity metadata (`activities/*/activity.json`)
     * Checkpoint timeline records (`activities/*/checkpoints/*.json`)
     * DAG relations (parent/child links, branch origins)
     * Related activity associations (`related_activity_ids`)
     * Workspace and subsystem configurations (`settings.json`, `privacy.json`, `retention.json`, `triggers.json`)
     * Explicitly approved artifact references and snapshot payloads
   - Excluded Non-Authoritative / Derived Content:
     * Ephemeral SQLite database files (`*.db`, `*.db-wal`, `*.db-shm`, `activities_idx`, `checkpoints_idx`, `search_fts`)
     * Temporary work files (`*.tmp`, `*.cache`, `*.~*`)
     * Runtime process/daemon tokens and lockfiles (`*.pid`, `*.token`, `session.token`)
     * Local retention audit/trash backups (`.continuum/retention_backups/*`)
     * High-risk secret files (`.env`, `.env.local`, `*.pem`, `*.key`)
   - Documented Rebuilt Derived Data:
     * The backup manifest explicitly enumerates which indexes (`activities_idx`, `checkpoints_idx`, `search_fts`)
       and in-memory caches must and will be rebuilt upon archive restoration, avoiding stale or bloated databases.

2. Integrity & Version Metadata (`core.backup.BackupManifest`):
   - Manifest stored at root of archive (`manifest.json`).
   - Format specification: `format_version="1.0.0"`, Continuum tool version, ISO 8601 creation timestamp.
   - Per-file manifest entries with 64KB chunk-streamed SHA-256 checksums (`file_manifest`).
   - Root archive SHA-256 integrity hash (`archive_sha256`).
   - Full summary of archived entities: counts of activities, checkpoints, artifacts, and config files.

3. Truthful Encryption Disclosure:
   - `manifest.encryption_status` strictly declares `"NONE"`.
   - Explicit disclaimer embedded in manifest and verify output: "Backup archive is unencrypted. SHA-256 checksums provide integrity verification, not encryption or confidentiality."
   - Never claims encryption without implementation.

4. Streaming & Bounded-Memory Behavior (I-17):
   - Uses 64KB streaming buffers (`CHUNK_SIZE = 64 * 1024`) for tar member creation, extraction, and SHA-256 hashing.
   - Never loads large archives or multiple snapshots into memory simultaneously.
   - Tested under high-volume simulated payloads with minimal memory overhead.

5. Broken Relation & Corruption Detection:
   - Validates DAG references before archive generation: detects broken parent checkpoint links and unrecorded branch origins.
   - Detects truncated archives, corrupted headers, tampered payload bytes, and schema mismatches.
   - User-safe exception hierarchy: `BackupError`, `UnsupportedBackupVersionError`, `CorruptedBackupError`, `MissingRelationError`, `BackupScopeError`.

6. REST API Control Plane:
   - `GET /api/v1/backup/scope`: Exposes authoritative included/excluded scope rules and rebuilt derived datasets.
   - `POST /api/v1/backup/create`: Generates streaming `.tar.gz` archive and writes integrity manifest.
   - `POST /api/v1/backup/verify`: Verifies archive structure, tar validity, file count, and SHA-256 checksums without modifying system state.
