1. EXECUTIVE SUMMARY & OBJECTIVE
--------------------------------------------------------------------------------
Phase 58 concludes Milestone 37 (Durable Storage and Migration) of Project Continuum
v1.4.0 "Universal Resume Anywhere". Conforming to invariants I-05 (Explicit & Safe
Restore), I-06 (Derived Briefs & Indexes), I-11 (Guarded Ancestry), and I-14
(Validated, Recoverable, Idempotent Operations), this phase implements:
1. `StorageConsistencyEngine`: Diagnostic auditing and safe recovery engine.
2. Full anomaly detection suite:
   - Orphaned checkpoints: checkpoints declaring mismatched activity_id.
   - Missing activity records: directories containing checkpoints but missing activity.json.
   - Invalid branch / parent references: checkpoints referencing non-existent parent IDs.
   - Malformed records: corrupt JSON or schema-invalid files.
   - Derived-index mismatches: discrepancy between authoritative disk JSON and SQLite index.
   - Stale temporary files: unlinked in-flight `.tmp` files from interrupted processes.
3. Explicit, Non-Destructive Repair:
   - Zero silent data loss: malformed files are quarantined with manifests into
     `<workspace_root>/.continuum/quarantine/<timestamp>/`, never deleted.
   - Missing activity headers are safely reconstructed, preserving all underlying checkpoints.
   - Broken ancestry references are quarantined into `metadata["unresolved_parent_id"]`,
     preserving the checkpoint and removing illegal graph cycles.
   - Derived SQLite index is deterministically rebuilt from authoritative JSON partitions (I-06).
4. Repeatable and idempotent operations: a second audit/repair pass confirms 100% clean state.

3. ARCHITECTURAL CONTRACTS & INVARIANTS ENFORCED
--------------------------------------------------------------------------------
A. Non-Destructive Recovery (I-05, I-14):
   - Corrupted or damaged records are moved into timestamped quarantine directories
     along with `.manifest.json` files documenting original path and failure reason.
   - No data is silently destroyed.

B. Ancestry Preservation & Graph Repair (I-11):
   - When a checkpoint references a non-existent parent, the invalid pointer is
     nulled on the relational edge while the referenced ID is preserved in
     `metadata["unresolved_parent_id"]`.

C. Derived-Index Resynchronization (I-06):
   - Index mismatches between disk files and SQLite are repaired deterministically
     by executing `store.rebuild_index_from_authoritative_files()`.

D. Repeatability & Idempotence:
   - Running `engine.repair()` on a repaired storage reports 0 issues detected and
     0 issues repaired, leaving storage in a verified clean state.
