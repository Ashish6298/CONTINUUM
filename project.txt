AI WORK CONTINUITY & AGENT HANDOFF SYSTEM (PROJECT "CONTINUUM")
COMPREHENSIVE PROJECT SPECIFICATION & ARCHITECTURAL FOUNDATION
================================================================================

1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
--------------------------------------------------------------------------------
Current generative AI software engineering workflows suffer from severe context
entrapment. A user's work, active architectural decisions, in-flight refactorings,
and uncommitted code logic become locked inside a particular AI agent's context
window, conversation history, model tier, or quota threshold.

When an AI conversation reaches its context limit, encounters rate caps, crashes,
or when the engineer desires to switch between models (e.g., Codex on Monday,
Claude on Tuesday, Gemini on Wednesday, Local Llama on Thursday), the context is
abruptly severed. Today's standard remedies—pasting chat logs, dumping entire
repositories into prompt windows, or asking an LLM to "summarize what we did"—fail
catastrophically:
- Blind LLM summaries compound hallucinations, turning partial work into false claims.
- Chat history dumping wastes millions of tokens on obsolete debates and failed attempts.
- Large context dumps overwhelm reasoning engines with irrelevant dependencies.

Project Continuum solves this fundamentally:
"Continuum creates a portable, mathematically verifiable, and model-independent
representation of the user's ongoing work state, enabling any subsequent AI agent
to seamlessly continue execution without restarting context or inheriting hallucinations."

Continuum does NOT recreate old conversations; it reconstructs the verifiable
reality resulting from the work.

--------------------------------------------------------------------------------
2. CORE VALUE PROPOSITION & END GOAL
--------------------------------------------------------------------------------
- Persistent, Universal AI Work Memory: Decouples progress from any single vendor,
  session, or context window.
- Verified Canonical State: Validates all claims against hard physical ground
  truth (ASTs, Git history, Test outcomes, Runtime status).
- Hallucination-Proof Handoffs: Introduces an evidence hierarchy and contradiction
  detection engine that explicitly calculates confidence scores per task.
- Context-Window Efficiency: Dynamically extracts only the relevant subgraph
  needed for the next immediate task, achieving up to 85% token reduction.
- End Goal: An omnipresent, lightweight developer engine and background daemon
  that guarantees zero lost work, seamless multi-agent collaboration, and zero-effort
  handoff across any existing or future AI platform.

--------------------------------------------------------------------------------
3. WHAT THE SYSTEM KNOWS, ANALYZES & GUARANTEES
--------------------------------------------------------------------------------

A. What the System Knows:
The system maintains strict ontological separation between three distinct realities:
1. Project State (Ground Truth):
   - What is physically true in the workspace (source code, AST signatures,
     manifests, Git tree, test reports, build status).
2. Conversational State (Intent & Reasoning):
   - What the user and AI discussed (user requirements, active architectural
     decisions, working hypotheses, unresolved dilemmas).
3. Agent Execution State (Tactical Intent):
   - What the previous agent was in the middle of doing (partially modified files,
     pending refactorings, broken intermediate tests, planned next steps).

B. What the System Analyzes (Multi-Source Evidence Harvesters):
1. Source Code & AST: Syntax trees, exposed interfaces, class diagrams, TODOs/FIXMEs.
2. Configuration & Manifests: Dependencies, lockfiles, runtime configs, Docker targets.
3. Version Control (Git): HEAD branch, working-tree diffs, staged blobs, recent commit log.
4. Verification Engines: Unit/Integration test suites, linter output, build logs.
5. Conversational Transcripts: Natural language user prompts, agent claims, and tool outputs.

C. What the System Guarantees:
1. Zero Hallucination Propagation: If an agent claims "Payment is complete" but
   no test passes or code is missing, Continuum marks it `INCOMPLETE` or `UNVERIFIED`
   with an explicit evidence audit trail.
2. Confidence Scoring: Every feature, phase, and component has a calculated
   confidence rating (0% to 100%) based on physical proof.
3. Complete Model Independence: Handoff packages are synthesized on demand into
   specialized formats (Claude XML, Codex/GPT Markdown+JSON, Gemini Hierarchical,
   Llama Compact) from a single vendor-neutral Canonical State.

THE EVIDENCE HIERARCHY MATRIX:
When evidence conflicts, Continuum resolves truth according to strict seniority:
Level 1 (Highest): Runtime status & automated test execution exit codes.
Level 2: Abstract Syntax Tree (AST) structure, symbol exports, and physical files.
Level 3: Git working tree diffs, staged index, and commit history.
Level 4: Architecture documentation, inline comments, and READMEs.
Level 5 (Lowest): Conversational statements and agent assertions.

5. CANONICAL STATE GRAPH (DAG) & CONFIDENCE SYSTEM
--------------------------------------------------------------------------------
Rather than relying on flat Markdown notes, Continuum represents the project as a
dynamic dependency graph:

[Milestone: Core Auth]
       │
       ├──► [Phase 1: DB Schema Migration] ── (Status: VERIFIED, Conf: 100%)
       │            │
       │            ▼
       └──► [Phase 2: JWT Service] ────────── (Status: PARTIAL,  Conf: 72%)
                    │                         (Issue: Token rotation stubbed)
                    ▼
            [Phase 3: Auth Controller] ────── (Status: BLOCKED,  Conf: 0%)
                    │                         (Dependency Phase 2 incomplete)
                    ▼
            [Phase 4: Mobile Integration] ─── (Status: PENDING)

Confidence Scoring Formula Principles:
- Implementation presence (AST export verified): +40%
- Test existence covering symbols: +25%
- Test execution passing (green exit code): +25%
- Git commit / history consistency: +10%
- Mismatch between docs/claims and code: Immediate flag + capped maximum score.

--------------------------------------------------------------------------------
6. THE MULTI-LAYER HANDOFF PACKAGE
--------------------------------------------------------------------------------
When exporting or transferring state to a new agent, Continuum produces four
specialized layers:

Layer 1: Canonical Machine State (`project-state.json`)
- Complete graph representation, dependency maps, confidence vectors, and metadata.
Layer 2: Human-Readable Summary (`project-context.md`)
- High-level architectural narrative, objectives, technology choices, and constraints.
Layer 3: Immediate Continuation Action (`handoff.md`)
- Laser-focused briefing for the incoming AI: exactly what file to open, what function
  to finish, what test is currently failing, and what assumptions are active.
Layer 4: Evidence Audit Trail (`evidence/`)
- Raw test logs, AST diff summaries, git churn stats, and contradiction reports.

--------------------------------------------------------------------------------
7. TARGETED CONTEXT SELECTION & MODEL ADAPTERS
--------------------------------------------------------------------------------
Instead of dumping 100k tokens of repository content into the new AI:
1. The developer or daemon specifies the next task: e.g., "Fix JWT refresh logic".
2. The Targeted Context Selector traverses the State DAG and selects only:
   - Upstream interfaces directly referenced by JWT logic.
   - The specific active unit tests (`auth_test.ts`).
   - Known architectural constraints for authentication.
   - The immediate uncompleted requirements.
3. The selected subgraph is passed through the Model Adapter:
   - Claude Adapter: Encapsulates context in structured semantic XML tags.
   - Codex/GPT Adapter: Generates markdown with structured JSON tool schemas.
   - Gemini Adapter: Structures markdown hierarchy with clear section demarcations.
